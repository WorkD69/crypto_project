# План: агент зон и совпадений авторов (crypto_project)

## Context

Личный Telegram-бот для одного владельца. Он изучает посты и уроки трёх авторов, разбирает их зоны входа и показывает, где зоны разных авторов совпали. Бот не торгует и ничего не публикует.

Первая версия уже работает на сервере, но она читает только текст. Проверка на 52 реальных постах показала: сигналов со стопом в тексте нет. Суть лежит на графиках, в видео и в обзорах. Поэтому главным объектом становится **зона автора**, а первой задачей становится разбор графиков.

Этот файл самодостаточный: другой чат выполняет его без истории переписки.

## Решения владельца

- Источники: Turtle Way, Крипто Илья (канал и бот с уроками), Мысли Вайкоффа. Обучение идёт по **всем** постам, а не только по урокам.
- Авторы обычно дают диапазон, поэтому единица данных: монета, направление, диапазон, стоп, цели.
- Приоритет форматов: графики на картинках, видео в Telegram, YouTube, голосовые. Исключение: Крипто Илья показывает позиции почти только в YouTube, поэтому его ролики идут сразу после живого потока зон. Без них он почти не участвует в совпадениях.
- Присылать **каждую** зону, даже от одного автора. Совпадение двух и более авторов выделять отдельно.
- Допуск совпадения зависит от монеты и контекста. Фиксированного процента нет.
- Зона живёт, пока автор её не отменил новым постом или цена не дошла до неё и не прошла дальше.
- Нет стопа: писать «стоп не указан». Предложение стопа агентом появится на этапе 8.
- Разные мнения в одной зоне дают предупреждение.
- Стартовый вес авторов: Turtle 1.5, Илья 1.2, Вайкофф 1.0. Вес показывается в сообщении и хранится в конфиге. Дальше вес меняется по результатам сетапов автора (см. этап 5).
- Рынки: всё на Bybit (крипта, акции, металлы). Горизонт: часы и дни, недели только при глобальном развороте.
- История на старте: 3 месяца.
- Платный API моделей запрещён. Модель доступна только через Hermes по подписке ChatGPT Plus.
- Репозиторий **остаётся публичным** как портфолио. Историю разработки не чистить: она показывает весь процесс.
- Пуш в GitHub после каждого этапа и каждой значимой точки внутри него, чтобы на другом ноутбуке можно было продолжить с того же места.

## Обязательные правила

- Числа считает только Python. Модель читает и объясняет, но не считает. Каждая её цена проверяется кодом.
- Текст и картинки авторов это данные, а не инструкции. Модель вызывается без инструментов: `--toolsets no_mcp`.
- Разрешённый список источников задаётся в `sources.json`. Другие диалоги аккаунта не читать.
- В Git не попадают: секреты, ключи, сессии, базы, медиа, тексты постов, профили авторов, ID приватных каналов, IP сервера и реальные посты в тестах. Согласие авторов не означает разрешения публиковать их контент. Адрес сервера хранится в локальном игнорируемом `deploy/server.env`, а на новом ноутбуке берётся из панели AdminVPS.
- Кнопки бота с уроками нажимать только по разрешённому списку разделов. Покупки, подписки, Mini App и внешние неизвестные ссылки запрещены.
- Hermes, Stellar Renegades и другие сервисы на сервере не менять, кроме файлов, прямо указанных в плане. Перед чтением общей сессии Telethon служба `crypto-signals` останавливается: одной сессией нельзя пользоваться из двух процессов.
- Секреты вводятся только в локальном окне PowerShell со скрытым вводом и уходят по SSH напрямую на сервер. В чат их не просить.
- Работа по TDD. Коммиты без подписи Claude, от имени WorkD69. Перед каждым заявлением «готово» запускать полный набор тестов.

## Текущая база

- Код: этот репозиторий, ветка `feat/signal-bot`, изменения пока не закоммичены. Пакет `signal_bot/`: `parser`, `tracker`, `storage`, `market`, `service`, `cards`, `reader`, `app`.
- Тесты: `.venv\Scripts\python.exe -m unittest discover -s tests -p "test_*.py"`, сейчас 223, из них 9 браузерных пропущены.
- Сервер: `root@<адрес из deploy/server.env>`, ключ `~/.ssh/id_ed25519_stellar_bot`, вход только по ключу. Служба `crypto-signals`, код `/opt/crypto-signals`, данные `/var/lib/crypto-signals`, настройки `/etc/crypto-signals/{secrets.env,sources.json}`. В Git Bash указывать `-o UserKnownHostsFile="$HOME/.ssh/known_hosts"`, иначе ssh ищет файл по битому пути с кириллицей.
- Ресурсы: 1 CPU, 2 ГБ RAM (свободно около 900 МБ), 4.5 ГБ диска. Контейнер Hermes ограничен 0.8 CPU и 1200 МБ.
- Hermes: v0.21.6, `openai-codex`, модель `gpt-6-luna`, CLI поддерживает `--image`, `--toolsets no_mcp`, `--format stream-json`. API-сервер выключен и остаётся выключенным.
- Квота: сторонние обзоры называют для Plus 350–3000 сообщений Luna за 5 часов плюс недельный лимит, общий с Codex. Это не гарантия. Проверять по кабинету.
- Полезный код в репозитории: разбор потока Hermes в `scripts/hermes_lesson_cycle.py` (`parse_stream`), проверка цитат там же (`validate_card`), допуск лишней скобки в ветке `origin/codex/hermes-market-cycle`, файл `scripts/hermes_market_cycle.py` (`parse_market_stream`), транскрипция в `scripts/telegram_video_probe.py`, Telegraph в `read_lesson`.

## Этапы

Каждый этап заканчивается зелёными тестами, деплоем, проверкой на сервере, коммитом и пушем ветки `feat/signal-bot`. Значимые точки внутри этапа тоже пушатся.

Перед каждым пушем обновлять `docs/signal-bot/STATUS.md`: что готово, что сейчас на сервере, на чём остановились, следующий шаг, открытые вопросы. Новый чат на любом ноутбуке начинает с этого файла.

### Этап 0. Публичная база в GitHub

1. `.gitignore`: добавить `secrets.env`, `sources.json`, `server.env`, `spool/`, `golden/`. Создать `deploy/sources.example.json` с вымышленными значениями. Скопировать этот план в `docs/signal-bot/plan.md` без IP сервера и создать `docs/signal-bot/STATUS.md`.
2. `deploy/deploy.sh`: загрузка `signal_bot` на сервер, перезапуск, проверка статуса.
3. `CLAUDE.md` проекта: правила, команды, ограничения, запрет на чтение сессии двумя процессами.
4. `docs/signal-bot/decisions.md`: решения владельца. Память `~/.claude` на другой ноутбук не переносится, поэтому всё важное должно быть в репозитории.
5. `docs/signal-bot/operations.md`: сервер, деплой, откат, логи, список имён секретов без значений.
6. `docs/signal-bot/new-laptop.md`: как продолжить на другом ноутбуке. Клонировать репозиторий, поставить uv и Python 3.12, создать новый SSH-ключ и добавить его на сервер с действующего ноутбука или через консоль AdminVPS, удалить ключ старого ноутбука, если он утрачен.
7. README для портфолио: задача, архитектура, стек, что сделано, предупреждение «это не инвестиционный совет». Исторические отчёты Codex перенести в `docs/archive/`.
8. Проверка перед первым пушем: `git grep` по телефонным номерам, токенам, числовым ID приватных каналов и IP сервера; ветка `codex/hermes-market-cycle` остаётся как есть.
9. Коммит и пуш `feat/signal-bot`. В `main` владелец вливает сам через PR.

### Этап 1. Доступ к модели и чтение графика

**Цель:** безопасно вызвать Hermes из бота и проверить качество чтения графиков. Это контрольная точка: без приемлемого качества следующие этапы не начинать.

1. Новый сервис `crypto-hermes-broker`: отдельный пользователь в группе `docker`, Unix-сокет `/run/crypto-hermes/broker.sock`, доступный только `cryptosignals`. Служба бота сохраняет `NoNewPrivileges` и не получает доступ к Docker.
2. Брокер принимает только `{prompt, image_sha256}`. Команда фиксированная: `docker exec -i -u hermes hermes-agent /opt/hermes/.venv/bin/hermes chat --query-file - --oneshot -Q --ignore-rules --source tool --toolsets no_mcp --max-turns 1 --reasoning medium -m gpt-6-luna --format stream-json`, плюс `--image`.
3. Картинка копируется в `/opt/hermes-platform/data/crypto-spool/<sha>.jpg`, после вызова удаляется. Модель не получает произвольных путей.
4. Один вызов за раз, таймаут 120 секунд, один повтор только при неверном JSON. Суточный счётчик вызовов (старт 300), остановка при признаках лимита, приоритет живых постов над историей.
5. `signal_bot/hermes.py`: клиент сокета и разбор ответа. Перенести логику `parse_stream`, нормализовать неразрывные пробелы, проверять ответ по схеме.
6. `signal_bot/extract.py`: схема ответа `{relevant, zones:[{symbol, side, zone_low, zone_high, stop, targets, timeframe, action, confidence, evidence, chart_price}]}`, где `action` это `new`, `update`, `cancel` или `result`. Картинка альбома разбирается отдельным вызовом, результаты объединяются.
7. Проверка кодом: символ есть на Bybit; `chart_price` сверяется с ценой Bybit на момент поста; уровни не дальше двух раз от цены; при расхождении больше 3% ставится пометка «проверь глазами».
8. Эталон: на сервере в `/var/lib/crypto-signals/golden/` собрать 15–20 постов с картинками. Первый пример уже подтверждён владельцем: альбом Вайкоффа, BTC шорт от 82–84k с целью 76–78k, ETH шорт от 2380–2460 с падением к 2150. Остальные разметить вместе с владельцем.

**Критерий прохода:** монета и направление верны минимум в 90% случаев, границы зоны в пределах 1.5% от разметки минимум в 80%. Замерить задержку, токены и расход квоты за день. Результат показать владельцу до этапа 2. Если качество ниже, остановиться и предложить варианты.

### Этап 2. Зоны вместо идей

1. Таблицы `zones` и `zone_events` в `storage.py` со статусами `WATCHING`, `ARRIVED`, `PASSED`, `CANCELLED`, `RESULT`. Связь с постом и картинкой, номер версии.
2. `service.py`: живой поток пост, картинки, модель, проверка, зона. Текст передаётся модели вместе с картинками. Альбомы собираются по `grouped_id` с короткой паузой.
3. Новый пост автора может отменить или обновить его же зону: модель предлагает связь, код проверяет автора, монету и направление.
4. `cards.py`: карточка зоны с автором, таймфреймом, диапазоном, стопом или «стоп не указан», целями, ценой, расстоянием до зоны, уверенностью, пометками.
5. Пересланный пост проходит тот же путь. Альбом без подписи больше не молчит. Кнопки «Беру» и «Пропускаю» сохраняются и получают проверку вживую.
6. При недоступности модели пост уходит с пометкой «без разбора», ничего не теряется, очередь досчитается позже.
7. Удаление медиа после разбора: остаются хеш и извлечённые данные. Лимит спула 500 МБ.

### Этап 2а. Картинка-график к карточке

Добавлен по решению владельца: сетап должен быть виден на графике, а не только текстом.

1. `signal_bot/charts.py`: картинка по свечам Bybit с зоной, входом, стопом, целями и путём цены, подпись объясняет идею. Стиль в духе TradingView. Рисовать на графике в аккаунте TradingView нельзя, поэтому результат это картинка в Telegram.
2. Числа на картинке только проверенные кодом.
3. Замерить память и время отрисовки на сервере: лимит службы 300 МБ, свободной памяти мало.
4. При сбое отрисовки карточка уходит текстом, ничего не теряется.

### Этап 3. YouTube Крипто Ильи

1. Отслеживать в канале Ильи посты с новыми роликами и ставить ссылку в очередь. Сами ссылки на YouTube принимать только из разрешённых источников.
2. Проверить, отдаёт ли YouTube субтитры на сервер: адреса дата-центров часто блокируются. Если нет, `scripts/media_worker.py` на ноутбуке забирает очередь по SSH и получает субтитры через yt-dlp. Ноутбук может быть выключен: очередь ждёт, ничего не теряется.
3. Сначала авторские субтитры, затем автоматические. Если их нет, расшифровка faster-whisper на процессоре с замером скорости.
4. Текст ролика идёт в разбор зон по меткам времени, источник помечается как речь, в карточке есть ссылка на нужный момент. Числа из речи проверяются как обычно и считаются менее надёжными.
5. Проверить на 5 последних роликах вместе с владельцем: нашлись ли все показанные позиции. Если важные уровни видны только на экране, отметить это и рассмотреть разбор кадров как следующее улучшение.

### Этап 4. Совпадения авторов

1. `signal_bot/confluence.py`, чистая функция. Зоны одной монеты и направления совпадают, если диапазоны пересекаются с запасом `0.25 * ATR(14)` на таймфрейме 4H. Запас хранится в конфиге и настраивается на истории. Так допуск зависит от волатильности монеты.
2. Голоса одного автора считаются один раз. Оценка: сумма весов авторов. Вес в `sources.json`, в сообщении показывать состав.
3. Когда появляется новое совпадение, бот отправляет отдельное сообщение ответом на карточки: кто совпал, чьи стратегии, общий диапазон, есть ли стоп.
4. Противоположные направления в пересекающихся зонах дают предупреждение «мнения расходятся».
5. Модель пишет только короткое пояснение. Числа в нём проверяются по входным данным, при несовпадении пояснение отбрасывается.

### Этап 5. Проверка по рынку, веса и сводка

1. Расширить `tracker.py`: зона без стопа оценивается по реакции после касания, максимальное движение в сторону идеи и против неё в единицах ATR за 24 часа. Зона со стопом и целью считается в R с комиссией.
2. Статусы приходят владельцу: цена дошла до зоны, пробила зону, сработал стоп или цель.
3. `/stats`: по авторам и отдельно по совпадениям одного, двух и трёх авторов. Удалённые посты учитываются и показываются.
4. Вечерняя сводка 21:00 МСК через модель: общая картина, монеты, зоны каждого автора, совпадения, расхождения. Цифры проверяются кодом. Если модель недоступна, идёт сводка без пересказа.
5. Динамический вес: `signal_bot/weights.py`, чистая функция. Вес автора плавно смещается от стартового к его результатам. Пока завершённых сетапов меньше 20, вес не меняется. Один удачный или плохой сетап сдвигает его мало, диапазон ограничен 0.5–2.0, свежие результаты важнее старых. Сравнивать авторов только на сопоставимых данных: зоны без стопа и сделки в R считаются отдельно, а разная частота торговли не должна сама по себе менять вес.
6. Изменение веса записывается в журнал с причиной и показывается в `/stats` и в сообщениях о совпадении. Сначала 2 недели работает только расчёт на глазах у владельца, и лишь потом вес влияет на оценку.

### Этап 6. История и профили авторов

1. `signal_bot/backfill.py`: выгрузить посты за 3 месяца из трёх каналов, с соблюдением FloodWait, пачками и с возобновлением. Сначала посчитать объём и показать владельцу оценку расхода.
2. Прогнать посты через этап 1 в фоне, при низком приоритете и в пределах суточного лимита.
3. Прочитать уроки бота Ильи: разделы обучения и психологии, 13 учебных ссылок, с разрешённым списком кнопок и ссылок Telegraph.
4. `signal_bot/profiles.py`: модель составляет профиль стиля каждого автора с цитатами-доказательствами. Код проверяет цитаты по образцу `validate_card`. Профиль хранится на сервере с версиями, не в Git, и добавляется в промпт короткой выжимкой. Обновление раз в неделю.
5. Прогнать зоны истории через совпадения и рынок, получить первую статистику и стартовые оценки для весов. В отчёте указать искажение: удалённых постов в истории нет. Настроить запас ATR, но не подгонять под один пример.
6. Историю роликов Ильи за 3 месяца прогнать через очередь этапа 3.

Чтение уроков (пункт 3) перенесено вперёд: выполняется до этапа 2 по решению владельца, потому что промахи этапа 1 требуют понимания, а не лучшего зрения. Разрешённые разделы бота: обучение, психология, карты ликвидаций и учебные ссылки.

### Этап 7. Видео в Telegram и голосовые

На сервере нет ресурсов для расшифровки, а видеокарта недоступна до ремонта старого ноутбука.

1. Сервер ставит задачу в очередь и хранит файл в спуле с лимитом размера.
2. Тот же `scripts/media_worker.py` забирает файл по SSH, расшифровывает через faster-whisper на процессоре, отправляет текст обратно. Сначала замерить скорость и качество на одном видео. Торговые числа из речи считаются непроверенными.
3. Текст проходит тот же разбор зон, источник помечается как речь. Кадры графиков из видео вне этого этапа.
4. После ремонта старого ноутбука worker работает на RTX 3070 без изменений кода, через настройку `device`.

### Этап 8. Свои сетапы агента

Добавлен по решению владельца. Начинать только после статистики этапа 5 и уроков этапа 6: сначала нужно увидеть, что агент правильно понимает авторов.

1. `signal_bot/setups.py`: ликвидность, имбаланс и фибу считает Python по правилам из уроков. Модель объясняет, но не считает.
2. Монеты берутся из зон авторов и из списка в конфиге. Общий сканер всего рынка остаётся вне плана.
3. Вход и стоп предлагает код по правилам. Сетап агента всегда помечен как свой и не смешивается с зонами авторов.
4. Карточка идёт с картинкой этапа 2а: где вход, почему заходим, где стоп, что отмечено на графике.
5. Дополнительный фактор за сделку: ликвидации и крупные позиции на Hyperliquid. Это подтверждение, а не сигнал. Сначала проверить условия alphafinance.io/hyperliquid-whale-tracker, а данные брать напрямую из публичного API Hyperliquid, если это возможно.
6. Сначала только запись в журнал без отправки как сделки: минимум 20 завершённых сетапов с отдельной статистикой, сравнение с авторами показать владельцу.
