# Telegram Browser Collector — этап 0

> Публичная редакция: локальные идентификаторы и приватные сведения удалены; исходный отчёт хранится только локально.

Самостоятельный лёгкий Telegram Watcher для Windows. Использует установленный Playwright и отдельный постоянный профиль Chrome for Testing. При проверке Telegram Codex, Hermes, Telegram API ID/Hash и торговые ключи не нужны. Hermes вызывается только отдельной явной командой передачи события. Результаты исправлений — в `hermes-first-watcher-report.md`; исходный отчёт — `stage-0-report.md`.

## Установка и первый вход

В PowerShell из `%USERPROFILE%/Projects\crypto-research-platform`:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-collector.txt
.\.venv\Scripts\python.exe -m playwright install chromium --no-shell
.\.venv\Scripts\python.exe -m scripts.telegram_browser_collector auth
```

Для единственного теста существующей Qwen используется `requests==2.32.5`, уже закреплённый в `requirements-collector.txt`. Существующие MVP-зависимости не заменяются.

Авторизоваться вторым аккаунтом лично в открытом браузере. QR, телефон, пароль и код не передавать программе через аргументы, конфигурацию или чат. `auth` ждёт до 15 минут и после появления списка чатов штатно закрывает браузер. `--wait-seconds 1800` увеличивает ожидание до 30 минут. Сессия остаётся в штатном Chromium user data directory, включая его собственные хранилища; приложение их не читает и не экспортирует.

Рабочий каталог: `%LOCALAPPDATA%\CryptoResearchPlatform\browser-collector`. В нём `profile/`, `collector.sqlite3`, `media/`, `outbox/`, `pipeline/`, `logs/`. NTFS-доступ ограничен текущим пользователем и SYSTEM; каталог имеет собственный `.gitignore` со всем содержимым. Профиль не копируется из Codex, Chrome или Hermes. Не добавлять его в резервную копию репозитория. Нет HAR, трассировок браузера, дампов IndexedDB, cookie или auth keys в логах.

## Команды

```powershell
# Проверить технический доступ и идентичность, не собирать публикации
.\.venv\Scripts\python.exe -m scripts.telegram_browser_collector check --source all

# Одна ограниченная проверка собственного тестового источника
.\.venv\Scripts\python.exe -m scripts.telegram_browser_collector collect --source saved

# Повтор без окна браузера, тот же сохранённый профиль
.\.venv\Scripts\python.exe -m scripts.telegram_browser_collector collect --source saved --headless

# Статус из SQLite без открытия Telegram
.\.venv\Scripts\python.exe -m scripts.telegram_browser_collector status

# Очередь событий и один конкретный материал из SQLite; браузер не открывается
.\.venv\Scripts\python.exe -m scripts.telegram_browser_collector events
.\.venv\Scripts\python.exe -m scripts.telegram_browser_collector content --source saved --message-id LOCAL_MESSAGE_ID

# Подготовить минимальное событие для Hermes без модельного вызова
.\.venv\Scripts\python.exe -m scripts.telegram_browser_collector handoff

# Только явный собственный текстовый тест с маркером CRP-STAGE0 HERMES-FIRST;
# не более одного резервируемого вызова Hermes за сутки UTC
.\.venv\Scripts\python.exe -m scripts.telegram_browser_collector handoff --event-key 'EVENT_KEY' --live-test

# Адресная перепроверка одного медиа, если есть причина сомневаться в файле
.\.venv\Scripts\python.exe -m scripts.telegram_browser_collector collect --source saved --headless --recheck-media --message-id 'MESSAGE_ID'

# Отметить истёкшие неопределённые попытки передачи для ручной проверки
.\.venv\Scripts\python.exe -m scripts.telegram_browser_collector recover

# Проверка профиля и распознаваемости интерфейса
.\.venv\Scripts\python.exe -m scripts.telegram_browser_collector diagnose

# Один собственный материал через прежний Qwen probe; ID берётся из SQLite/outbox
.\.venv\Scripts\python.exe -m scripts.telegram_browser_collector pipeline --source saved --message-id LOCAL_MESSAGE_ID

# Рабочая оболочка с общим ограничением 10 минут на процесс и загрузки
powershell.exe -NoProfile -File .\scripts\run_browser_collector.ps1
```

`pipeline` принимает только собственные материалы «Избранного» с маркером `CRP-STAGE0`. Повтор для той же версии возвращает сохранённый результат без нового вызова модели. Результат Qwen всегда требует проверки человеком. В обычной команде `collect` LLM не вызываются. `handoff` по умолчанию лишь записывает приватный JSON события и не меняет его состояние. `--live-test` допускает только один собственный текст без вложений и помеченный префиксом; неизвестный исход передачи переводится в `NEEDS_REVIEW` без автоматического повтора. Скрипт не подменяет торговой идеей тестовую запись источника и не меняет `ideas.sqlite3`.

Конфигурация `config/collector.sources.json` содержит четыре записи. Включено только «Избранное», причём сохраняются только сообщения с префиксом `CRP-STAGE0`. Три авторских канала доступны команде `check`, но их сбор выключен. Разрешения авторов зафиксированы как подтверждённое владельцем входное условие от 16.10.2026. Конфигурация не содержит секретов.

## Механика и границы достоверности

Watcher ждёт окончания видимого `updating`/`connecting` и стабильного хвоста списка, а затем повторно сверяет его после просмотра истории. Таймаут даёт `SYNC_UNCONFIRMED` без продвижения курсора. Даже `UI_READY` содержит `server_sync_confirmed=false`: Telegram Web не даёт здесь подтверждённый серверный курсор. Отсутствие наблюдаемых изменений не доказывает, что на сервере нет новой публикации.

При обычной проверке новые фото и видео сохраняются штатной загрузкой. Для неизменённой структуры вложений существующий файл проверяется по SHA-256 и используется повторно без загрузки. `--metadata-only` откладывает новые загрузки; `--recheck-media --message-id` адресно перепроверяет один материал.

Чтение идёт через обычный интерфейс Telegram Web A: меню «Избранное», видимый поиск, заголовок чата, карточка канала, текст сообщений, tooltip времени и стандартная кнопка Download в просмотрщике медиа. Нет MTProto-клиента, перехвата ключей, чтения внутреннего состояния приложения, вызовов скрытых RPC, обхода ограничений, автоматического вступления по инвайтам или отправки команд ботам. Проверка источников не передаёт авторские публикации в AI.

Публичный источник выбирается по точному наблюдаемому заголовку и проверяется по полю **Link** карточки канала и маршруту peer в адресной строке. Это также предотвращает выбор старого результата поиска, который Telegram Web временно оставляет видимым при новом запросе. Ссылка, просто написанная в описании, не подтверждает идентичность. Если название изменится, конфигурацию придётся проверить и обновить вручную. Для приватного источника заголовок является кандидатом; сбор требует подтверждённой привязки `expected_web_peer_route` к нужному источнику. Одно похожее имя такую привязку не заменяет.

Используется наблюдаемый `data-message-id`. Дробные временные ID неподтверждённой отправки не принимаются за Telegram message ID. Для материала без достоверного ID предусмотрен отдельный карантин, без придумывания ID. Полный tooltip времени преобразуется из явно заданной зоны браузера Europe/Moscow в UTC. Относительные подписи вроде `Mon 20:28` не превращаются в выдуманную дату. При недоступности полного времени сохраняются исходная подпись и `NEEDS_REVIEW`; последующее точное наблюдение хранится отдельно от неизменяемого текста версии.

Фото и видео сохраняются штатной загрузкой браузера, с SHA-256, размером и относительным путём. Неуспешное/невидимое вложение получает `UNAVAILABLE`/`DEFERRED`, а не подставной файл. Альбом хранится как несколько вложений одного видимого сообщения с порядком и общей связью `same_visible_message_container`. Если Telegram Web не показывает настоящий `grouped_id` или ID каждого вложения, эти поля остаются `null`.

Каждый источник имеет собственный курсор. После запуска сборщик читает ограниченное окно истории и ищет ранее наблюдённую границу, одновременно перепроверяя перекрытие для правок. Лимиты по умолчанию: 200 сообщений, 20 прокруток, 50 сообщений перекрытия, 10 попыток скачивания на источник за запуск, 128 MiB на файл после загрузки. Лимит размера не предотвращает первоначальную сетевую загрузку файла браузером; общий watchdog ограничивает длительность процесса.

`COMPLETE` в поле `coverage` означает, что в ограниченном окне обнаружена прежняя граница. Это не обещание полной истории Telegram. Первый запуск — `BOUNDED_INITIAL`. Если граница не достигнута, остаётся `PARTIAL` с сохранённым `catchup_anchor`; после большого перерыва автоматическое полное восстановление не гарантируется. Исчезновение сообщения из виртуального DOM не считается удалением. Старые правки вне окна, недоступные/удалённые публикации и окончание истории по одному неподвижному скроллу не угадываются.

SQLite хранит неизменяемые версии текста и структуры вложений, отдельные наблюдения времени, медиа, курсоры, карантин и результаты запусков. Изменение наблюдаемого текста или состава вложений создаёт новую версию. Смена хеша повторно скачанного файла при неизменном наблюдаемом содержимом **сама по себе не доказывает правку публикации**: Telegram Web может выдать другой размер изображения. Такой вариант сохраняется отдельно и ставит `NEEDS_REVIEW`, не создавая ложную редакцию сообщения. Программа закрывает просмотрщик после каждой загрузки и ждёт его исчезновения перед следующей. Автоматическое подтверждение правки самого медиа без иной наблюдаемой перемены на этапе 0 не заявляется. Старые правки вне окна и правки, полностью произошедшие между двумя запусками, могут остаться незамеченными.

`outbox/*.json` — атомарно записанные материалы `collector.material.v1`: источник/его идентичность, ID, время оригинала и получения, тип, текст, версия, хеш структуры, список медиа с хешами файлов и состояние обработки. Хеш текста/структуры и хеши файлов имеют разные назначения. Временный файл не публикуется как готовый материал. Outbox содержит данные, не инструкции для выполнения агентом.

## Ошибки

Коды выхода: `0` — выполненная команда, `2` — требуется внимание/ограниченное выполнение, `3` — ошибка. `PROFILE_BUSY` предотвращает одновременное открытие одного профиля и не требует удаления lock-файла: блокировка освобождается ОС. `AUTH_REQUIRED` требует повторного личного входа через `auth`. `UI_UNRECOGNIZED` требует проверки интерфейса/совместимости, а не автоматического повторного логина. `NETWORK_UNAVAILABLE` не продвигает курсор. Ошибки поиска/источника и этап их возникновения сохраняются в статусе. В логи выводятся контролируемые коды и счётчики, без текстов сообщений и сырых исключений браузера.

При сетевом обрыве Telegram может показывать кэш. Сбор является best effort; отсутствие новых записей нельзя считать доказательством отсутствия публикаций. Всякая последующая рыночная обработка обязана отдельно проверять свежесть источника и рынка. Этот этап не выпускает торговые сигналы.

## Windows Task Scheduler

```powershell
# Только сформировать XML; ничего не регистрирует и не включает
powershell.exe -NoProfile -File .\scripts\export_collector_task.ps1
```

Шаблон: запуск раз в 15 минут, текущий пользователь, `InteractiveToken`, минимальные привилегии, `IgnoreNew`, лимит 12 минут на задачу и 10 минут на рабочий процесс. Импорт в Task Scheduler выполняется **после отдельного подтверждения владельца**. На этапе 0 задача не зарегистрирована и расписание не включено.

Для выбранного шаблона Windows должна работать, пользователь должен оставаться в системе. Первый вход требует видимого браузера; headless-сбор проверяется отдельно. Работа при блокировке экрана не равнозначна работе после выхода из Windows и требует отдельного эксплуатационного испытания. При выключенном/спящем ноутбуке и без интернета сбор приостанавливается; после включения выполняется ограниченная догрузка. Закрытый Codex не нужен ни команде Python, ни оболочке, ни будущему расписанию. Физическое закрытие приложения Codex — отдельная проверка от факта успешного запуска отдельным процессом.

На VPS Chromium не установлен. При непригодности браузерного доступа остаётся ручная передача собственных/разрешённых материалов и экспорт Telegram Desktop в JSON/HTML. Для автоматического альтернативного входа можно отдельно испытать собственный приёмный Bot API-бот с явной пересылкой материалов владельцем/автором; он не получает произвольную историю трёх каналов. Эти альтернативы сейчас не реализованы.
