# Этап 0 — независимый Telegram Browser Collector

> Публичная редакция: локальные идентификаторы и приватные сведения удалены; исходный отчёт хранится только локально.

Испытания: **16–17.10.2026**, Windows, часовой пояс Europe/Moscow. Итог: **PARTIAL**. Самостоятельная программа, сохранение входа, чтение, новые сообщения, правка, фото/видео/альбом, дедупликация, ограниченная догрузка и локальный pipeline проверены. Полная привязка приватного источника к инвайту, реальный отзыв действующей сессии и физическое закрытие приложения Codex не подтверждены этим испытанием. К следующим этапам разработка не переходила.

## Что реализовано

- `scripts/telegram_browser_collector.py`: самостоятельные команды `auth`, `check`, `collect`, `status`, `diagnose`, `pipeline`.
- `scripts/collector/`: изолированный persistent profile и блокировка; конфигурация; Telegram Web A UI-адаптер; извлечение текста/подписей/времени; штатные загрузки медиа; SQLite-версии, курсоры, наблюдения и outbox; мост к прежнему Qwen probe.
- `scripts/collector_fixture.py`: отдельный явный генератор собственных тестов только в «Избранном». Запланированный читатель ничего не отправляет и не редактирует.
- `scripts/run_browser_collector.ps1`: запуск Python без Codex, headless по умолчанию, приватные логи и ограничение времени 10 минут на дерево процесса.
- `scripts/export_collector_task.ps1`: только экспорт Task Scheduler XML для интервала 15 минут. **Задача не зарегистрирована, постоянное расписание не включено.**
- `config/collector.sources.json`, `requirements-collector.txt`, два новых файла тестов, инструкция `browser-collector.md` и архитектурные границы `architecture-constraints.md`.

Проект не создан заново. Исправленный план был доступен в переписке; отдельного сохранённого файла плана в `docs` при начале работы не было. Изучены существующие отчёты, исходники обработки текста/медиа/видео, рыночной аналитики, дневника и тесты. Исторические результаты MVP не переименованы в новые живые проверки.

Рабочие доказательства находятся в `%LOCALAPPDATA%\CryptoResearchPlatform\browser-collector`: `collector.sqlite3`, `outbox/`, `media/`, `fixtures.jsonl`, `outage-before.json`, `standalone-result.json`, `session-loss-check.json`, `offline-check.json`, `pipeline/saved-LOCAL_MESSAGE_ID-v1.json`, `logs/`. Это локальные данные, исключённые из Git. В техническом статусе отдельно видны ошибки ранних прогонов; они не удалены ради чистого отчёта.

В последнем полном повторе два материала требовали проверки (`review_items=2`): один из-за метаданных, второй из-за неопределённого варианта изображения. Значение `coverage=COMPLETE` не означает, что все поля или выводы готовы к публикации. Непроверенные даты/выводы не превращались в торговые данные.

При проверке 17.10 ранняя логика ошибочно создала версию 2 альбома `LOCAL_MESSAGE_ID` только из-за смены SHA-256 первого JPEG при прежнем тексте и составе вложений. Первый файл имел 800×400 px, второй 1200×600 px; измеренная средняя разница после приведения размера составила 2,73/255 на канал, что согласуется с другим вариантом разрешения того же изображения. Это **не засчитано как правка Telegram**. Версия 2 оставлена в неизменяемой истории, а выдача материала помечена `MEDIA_BYTES_CHANGED_UNVERIFIED` и `NEEDS_REVIEW`. Логика исправлена: просмотрщик явно закрывается и проверяется перед следующим файлом; новая смена байтов при неизменном наблюдаемом содержимом отправляется на проверку без новой версии. После исправления проведены два чистых повтора. Автоматическое обнаружение правки только самих байтов медиа пока не доказано.

В поиске встречался одноимённый положительный peer — пользователь/бот; такой результат нельзя принимать за канал, добавлена отдельная проверка типа. |

Повторные проверки выявили, что Telegram Web временно оставляет результаты предыдущего поискового запроса в DOM. Первый общий запуск ошибочно открывал старый канал, но проверка Link отказала в его принятии. Исправлен выбор точного отображаемого заголовка; затем общий запуск `check --source all --headless` дал `VERIFIED` для обоих публичных каналов, `NEEDS_BINDING` для приватного и `VERIFIED` для собственного источника. Несоответствие даёт отказ, а не запись из похожего источника. Массовой выгрузки/AI-обработки трёх каналов нет. Все три записи `enabled=false`.

Разрешения авторов приняты как данность и зафиксированы в конфигурации. Оставшаяся привязка приватного peer — техническая задача определения источника, не повторное согласование прав. Перед включением его сбора требуется подтвердить соответствие конкретного канала исходному инвайту; одного названия недостаточно. Автоматическое вступление по инвайтам не выполнялось.

## Автоматические тесты

```powershell
$env:COLLECTOR_BROWSER_TESTS='1'
.\.venv\Scripts\python.exe -m unittest discover -s tests -p 'test_*.py'
```

**52 теста, все прошли:** прежние 16 сохранены, новые 29 проверяют конфигурацию, реальные SQLite-записи/версии, карантин, курсоры, блокировку профиля, даты, отказ от пользовательского peer вместо канала, отличающиеся байты медиа без доказанной правки и границы локального pipeline; 7 тестов используют реальный Chromium с локальным синтетическим DOM и стандартным скачиванием, включая старый результат поиска и явное закрытие просмотрщика. Без `COLLECTOR_BROWSER_TESTS=1` семь браузерных проверок явно пропускаются, а не считаются успешными.

Live Telegram и локальные DOM-тесты являются разными проверками. Они не доказывают стабильность Telegram Web на недели и месяцы, обработку всех типов сообщений, больших видео, неизвестных альбомных раскладок или всех вариантов потери авторизации.

## Ресурсы и инфраструктура

- Установлены в проектную `.venv` Playwright **1.61.0** с небольшими зависимостями и `requests==2.32.5` для прежнего Qwen probe. На Windows установлен соответствующий Chrome for Testing **149.0.7827.55**; архив загрузки **183,6 MiB**. Модели Whisper/Qwen не заменялись.
- Рабочий каталог коллектора при замере занимал **102,3 MiB**, включая профиль, кэш, небольшие тестовые файлы и диагностику. Дистрибутив Chromium хранится отдельно в стандартном Windows-кэше Playwright.
- Один выборочный замер связанных Chrome-процессов дал сумму working set **875,9 MiB**. Это не измерение пика или полной приватной памяти дерева, общие страницы могут учитываться неоднократно. Малому VPS с работающим Hermes такой браузер сейчас не назначается.
- Один вызов локальной Qwen. **Hermes/Luna: 0, Sol: 0, платных API: 0 в потоке этапа 0.** Обычные запуски коллектора не вызывают LLM. Потребление самой текущей сессии разработки Codex в эти счётчики не входит.
- VPS, Hermes, его контейнеры/маршрутизация/память/Cron, бот дяди и игровые боты не изменялись. SSH-команд к ним в этой реализации не было. Публичные порты, торговые ключи, ордера и публичные публикации отсутствуют.

SQLite-дневник `artifacts/mvp_02_03/ideas.sqlite3` не изменён. SHA-256 до и после: `LOCAL_HASH_OMITTED`. Исходники прежних MVP-скриптов не переписывались. Git при исследовании определял корнем `C:/`, а не этот проект: корневые ветки, история и конфигурация Git не изменялись, коммиты/публикация не выполнялись.

## Ограничения и решение по этапу

Независимый Browser Collector **технически пригоден для продолжения испытаний на ограниченном наборе материалов**, но его нельзя объявлять эквивалентом официального API с гарантией всех событий. Это polling виртуального, изменяемого интерфейса: старые правки вне окна, промежуточные правки между запусками, удаления, недоступные оригиналы и большие пропуски не гарантированы. Полный timestamp может быть недоступен; сохраняется `null`/сырой текст и статус проверки. Альбомная связь — наблюдаемая DOM-группа; неизвестные серверные ID не восстанавливаются. Смена байтов загруженного изображения при прежнем тексте и составе вложений требует проверки человеком и не считается доказанной авторской правкой.

Без работающего Windows-ноутбука Telegram-сбор приостанавливается. Headless-режим работает, выбранный будущий шаблон Task Scheduler требует входа текущего пользователя в Windows. Работа на заблокированном экране, после выхода из Windows, после реального отзыва авторизации и при физически закрытом Codex не проверена. Круглосуточный мониторинг и эксплуатационная устойчивость не заявляются.

Остаются три конкретных проверки: точная привязка приватного канала; запуск с физически закрытым Codex в обычном пользовательском сеансе; продолжительное наблюдение нескольких разрешённых тестовых обновлений с контролируемым перерывом и повторной авторизацией при необходимости. Постоянное расписание включается только по отдельному подтверждению владельца. При непригодности UI остаются ручной импорт/Telegram Desktop export; отдельный приёмный Bot API-бот с пересылкой — проверяемая будущая альтернатива, без обещания истории чужих каналов.

**Этап остановлен на отчёте PARTIAL. Этапы 1–8 не начаты.**
