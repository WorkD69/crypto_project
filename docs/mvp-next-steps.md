# После MVP 0.2–0.3

1. Получить явные разрешения на конкретные сторонние Telegram-посты, изображения и видео для выбранного AI-процесса; отдельно определить право на производные публикации. Хранить минимум данных и предусмотреть отзыв.
2. Составить небольшой размеченный эталонный набор по разрешённым материалам. Раздельно измерить качество текстового извлечения, OCR/vision Qwen, русской транскрипции и ручной сверки чисел. Для видео попробовать более точную локальную multilingual-модель и сравнить с ручной проверкой.
3. Согласовать формальные правила для каждого источника с примерами и контрпримерами. Для Wyckoff Company отдельно выяснить опорные точки Fibonacci 1.414/1.618; для Turtle Zone проверить автора, Pine-код и условия повторного использования до реализации на Bybit.
4. В Codex Plan Mode спроектировать слой `source → thesis → factor → market snapshot → decision → chart → post`, архив версий правил, воспроизводимый replay без будущих свечей и тестовые разрешённые публикации.
5. Усилить дневник: пагинация Bybit для длинных горизонтов, учёт пропущенных свечей, отдельное событие подтверждения исполнения, несколько целей, комиссии/проскальзывание, явные условия инвалидации и аудит обновлений.
6. Для дальнейшей интеграции Telegram добавить выбор собственного канала, проверку превью, идемпотентность и повторную проверку актуальности рынка непосредственно перед публикацией. В этом MVP вручную проверены одно сообщение в «Избранном» и его message ID.
7. Бэктестить только формализованные правила с фиксированными срезами времени и отдельно оценивать ложные совпадения факторов. Не оптимизировать пороги по единственному текущему примеру.
